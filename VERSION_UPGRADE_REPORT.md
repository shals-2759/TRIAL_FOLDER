## `actions/checkout`

**Summary:** This upgrade from v4 to v7 of `actions/checkout` involves several critical changes, including minimum Node.js and runner version bumps, changes in credential persistence, and a new security hardening feature that blocks checking out fork PRs in specific contexts. Users should carefully review and update their self-hosted runners and adjust workflows to accommodate these breaking changes.

### ⚠️ Breaking Changes

- **[CRITICAL]** Starting with v5.0.0, the action requires Node.js 24. Older Node.js versions on self-hosted runners may not be compatible.
- **[CRITICAL]** Version 5.0.0 introduces a minimum compatible Actions Runner version of v2.327.1.
- **[WARNING]** In v6.0.0, the `persist-credentials` mechanism changed to store credentials under `$RUNNER_TEMP` instead of directly in the local git config. This may affect Docker container actions relying on direct credential access.
- **[CRITICAL]** For Docker container action scenarios utilizing persisted credentials (from v6.0.0+), a minimum Actions Runner version of v2.329.0 is required.
- **[CRITICAL]** Version 7.0.0 blocks checking out fork PRs when using `pull_request_target` and `workflow_run` event contexts due to security hardening. Workflows relying on this behavior will fail.
- **[INFO]** Version 7.0.0 upgrades the action's internal modules to ESM (ECMAScript Modules) from CommonJS.

### ✨ New Features

- Support for partial checkout filters (v4.1.0)
- Added SSH user parameter (v4.1.3)
- Added Ref and Commit outputs (v4.2.0)
- Improved handling for checking out other refs/* by commit, including fallback to ref if commit provided (v4.1.7, v4.2.1)
- Added support for checking out internal repositories when checking out multiple repositories (v4.3.0)
- Added worktree support for `persist-credentials includeIf` (v6.0.1)
- Added `orchestration_id` to git user-agent when `ACTIONS_ORCHESTRATION_ID` is set (v6.0.2)
- Fixed checkout initialization for SHA-256 repositories (v6.0.3)

### 🛠 Migration Steps

1. Ensure GitHub Actions self-hosted runners are updated to a version that supports Node.js 24, or verify GitHub-hosted runners are up-to-date.
2. Update self-hosted GitHub Actions runners to version v2.327.1 or newer.
3. If using Docker container actions that rely on `persist-credentials` and manually accessing git credentials, update your access method to look under `$RUNNER_TEMP`.
4. If using Docker container actions with persisted credentials, update self-hosted GitHub Actions runners to version v2.329.0 or newer.
5. Review workflows utilizing `pull_request_target` or `workflow_run` that previously attempted to check out code from forked pull requests. Adjust workflow logic or consider alternative secure patterns if this functionality is still needed.
6. No direct user action is expected unless your workflow deeply interacts with the action's internal module system and assumes CommonJS.
